# Factory Site Playbook（工厂独立站建设手册）

一份面向 B2B 外贸独立站的 WordPress 全流程手册——工厂真正需要的那种，而不是代理公司卖的那种。

以 agent skill 形式编写：把文件夹放进编码助手的 skills 目录即可按六阶段路由工作；当作文档阅读也完全成立。

> **许可先说清楚。** `scripts/` 是 MIT。其余所有内容——`references/`、`assets/`、`SKILL.md`、两个 README——是 **CC BY-NC-SA 4.0**：必须署 YB-L、不得商业转售、改后必须同协议公开。详见[许可](#许可)。

由 **[YB-L](https://github.com/uncle22)** 在长期建设与维护华南制造业 B2B 外贸站的过程中沉淀。方法留在这里，商业细节刻意不写。

## 用之前先看这一段

这是**从业者的手册，不是教程**。写给已经会建站、也已经懂搜索的人，缺的是那部分没人写下来的东西：先后顺序、失败模式，以及只有在站点上线一年后才会明白的规则。

你至少得能独立应付这些，否则读起来会很吃力：

- HTML 和一种模板语言（示例是 PHP，但推理与具体技术栈无关）
- SSH、SFTP、命令行
- 技术 SEO 词汇：canonical、hreflang、sitemap、结构化数据、抓取预算
- WordPress 后台之外的层面：`wp-cli`、数据库、主题文件
- 分析工具与同意管理，熟到能对一份转化报告起疑

它**不会**教你怎么装 WordPress、选主题、买域名、挑插件、写第一篇文章——那些内容到处都是，这份从它们停下的地方开始。

如果你是第一次把网站搞上线，事故库会读起来很吓人，检查表会显得过分。那是因为写它的人已经先被烧过一次。

## 为什么写这个

大多数"如何做 B2B 网站"的内容来自没上线过站点的人：列插件、推主题，在真正会出问题的环节之前就停笔了。

这本手册相反：**每条规则背后都挂着一次真实生产事故**：

- 对主题目录执行 `chmod -R 644`，全站白屏式兜底渲染——而每个页面仍返回 HTTP 200、每个文件 `php -l` 全过。
- 清缓存请求打在 80 端口，返回 `200`，实际什么都没清——nginx 用 301 吞掉了 `PURGE` 方法，缓存陈旧数周而我们以为它在工作。
- 整页缓存把带过期 nonce 的表单页发给访客，真实询盘被静默拒绝。
- 线上模板急修后没回写受控副本，几周后一次正常部署把改动整体回滚，页面"丢"了一块没人记得的内容。

这些没有一条出现在插件教程里。全部收录在 [`references/90-failure-library.md`](references/90-failure-library.md)。

## 适合的场景

- 从代理公司手里接过 WordPress 站、要自己维护的运营或开发。
- 有产品目录 PDF、没有人手做站，但公司里有人真的能建。
- 有 WordPress 站、有流量、没询盘的外贸公司。
- 要给第二条产品线复刻同一个站、并且拒绝从零再来一遍的人。

假设 WordPress、PHP 模板，以及愿意碰代码。不假设有买企业级工具的预算。

## 事故库三条样例

**返回 200 的坏站。** 一次批量权限变更对主题目录用了 `chmod -R 644`。目录没有执行位就无法被遍历，PHP 进不去主题，WordPress 回退到裸渲染。每个 URL 都 200，每个文件 lint 都过。知道原因后修复只要四分钟；找到原因花了一小时，因为症状指向代码，真因是一个权限位。

**报告成功的清缓存。** `curl -X PURGE http://example.com/` 返回 `200`，部署脚本记录成功。实际是 nginx 用 301 应答了请求，重定向不携带 `PURGE` 方法，Varnish 从未收到。那段时间的所有部署都用陈旧 HTML 做了验证。修法是把 `PURGE` 用 `--resolve` 直连源站的 443，并用裸 URL 加浏览器 UA 复核——因为缓存页永远不会执行 PHP。

**死在缓存里的 nonce。** 落地页表单用 WordPress nonce 做 CSRF。整页缓存开启后，含 nonce 的 HTML 被发给所有人数小时。nonce 会过期，于是下午的每一次提交都校验失败——而表单看起来没问题，因为失败发生在服务端。修法是缓存页上不再把 nonce 当硬门槛，改用蜜罐加 IP 限流。

## 怎么用

**作为 agent skill。** 把文件夹复制进 skills 目录（`~/.claude/skills/`、`~/.workbuddy/skills/` 等）。`SKILL.md` 的 frontmatter 声明了触发条件，agent 会按所处阶段加载对应 reference，而不是凭感觉干活。

**作为手册。** 动手之前读 P0；第一次部署之前读 P5；第一次遇到"完全说不通"的故障时把事故库开着。

**作为建站顺序。** 新站按序走；老站各阶段独立。P1 和 P2 是最容易被跳过的，也是决定第二年好不好维护的。

## 脚本

| 脚本 | 用途 |
|---|---|
| `scripts/site_audit.py` | 站点指纹：CMS、主题、插件、sitemap 健康度、重图、hreflang |
| `scripts/check_links.py` | 批量查 URL 状态码与重定向 |
| `scripts/allintitle.js` | 无头 Chrome 跑 Google `allintitle:` 并读结果数 |
| `scripts/image_pipeline.py` | 方形裁切、WebP 转换、质量与压缩力度控制 |
| `scripts/deploy_theme_file.py` | 上传、lint、备份、清缓存、断言复核——凭据全走环境变量 |
| `scripts/fix_permissions.py` | 诊断并修复主题目录权限（目录 755、文件 644） |

所有脚本凭据一律读环境变量，代码里没有任何硬编码。
